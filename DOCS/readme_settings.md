## 2. Алгоритм работы (Логика)


В самом начале у нас написано следующее:
```bash
import os 
from dotenv import load_dotenv
from pathlib import Path
   ```

**`import os`**  - стандартный модуль для работы с операционными системами

**`dotenv`**  - библиотека позволяющая загружать файлы из **`.env`** 

**`pathlib import Path`** - вообще крутая штука которая предоставляет путь к файлу как обьект а не как обычную строку

Вместо **`"/home/user/project/settings.py"
`** мы пишем **`Path("/home/user/project/settings.py")
`**

Дальше идёт 

```bash
BASE_DIR = Path(__file__).resolve().parent.parent
   ```
Определяет где находится корневая папка проекта, и от неё зависят все пути

Если кратко, то нам её вообще трогать не надо

```bash
load_dotenv(BASE_DIR / ".env")
   ```

Эта строка загружает ключи, пароли из файла **`.env`** чтобы их можно было безопасно использовать через **`os.getenv()`** и не хранить в коде

```bash
SECRET_KEY = os.getenv('SECRET_KEY')
   ```

Берёт значение переменной **`.SECRET_KEY`**  из файла **`.env`** 

```bash
DEBUG = os.getenv('DEBUG', 'True').lower() == 'true'
   ```
Эта строка берёт значение DEBUG из файла .env как текст.
Потом она превращает этот текст в маленькие буквы и проверяет, равно ли он слову true.
В итоге мы получаем настоящее булево значение True или False, чтобы Django понимал, включён режим отладки или нет.

```bash
ALLOWED_HOSTS = [host.strip() for host in os.getenv('ALLOWED_HOSTS', '').split(',') if host.strip()]
   ```
Эта строка берёт из .env список доменов, разделённых запятыми (например: localhost,127.0.0.1,mydomain.com)
Потом она превращает эту строку в список Python, убирая пробелы и пустые элементы
Django будет принимать запросы только с этих доменов это типо защита от поддельных запросов

```bash
INSTALLED_APPS = [
    'django.contrib.admin',
    ...
    'zetom'
]
   ```

Это установленные приложения в django которые мы сейчас юзаем
Первые 6 это стандартные приложения которые и должны быть, ну а последний zetom это уже наше кастомное где находится бизнес-логика

```bash
MIDDLEWARE = [
    ...
]
   ```

MIDDLEWARE — это список через которые проходит каждый HTTP‑запрос, прежде чем попасть в view‑функции

Краткое описание каждой строки (спс гпт что он описал это кратко)

SecurityMiddleware — включает базовые защиты (HTTPS, заголовки безопасности).

SessionMiddleware — включает работу с сессиями пользователей.

CommonMiddleware — добавляет полезные функции (например, обработку слэшей в URL).

CsrfViewMiddleware — защищает формы от CSRF‑атак.

AuthenticationMiddleware — связывает пользователя с запросом (request.user).

MessageMiddleware — позволяет показывать всплывающие сообщения (alerts).

XFrameOptionsMiddleware — защищает от clickjacking‑атак.

```bash
ROOT_URLCONF = 'dcrm.urls'
   ```
Строка говорит Django, где находится главный файл маршрутов (URL‑адресов) проекта

```bash
TEMPLATES = [ 
   ...
]
   ```

Этот блок настраивает, как Django будет искать и обрабатывать HTML‑шаблоны

```bash
'BACKEND': '...',
   ```
Указывает какой шаблонизатор использовать
В нашем случае на данный момент там стандартный шаблон от django.
Проще говоря это рендер HTML с помощью стандартного Django‑движка

```bash
'DIRS': [],
   ```
Список дополнительных папок в проекте, где django будет искать шаблоны

```bash
'APP_DIRS': True,
   ```

Django автоматически ищет шаблоны внутри проекта
Если значение **`False`** то django не ищет шаблоны внутри проекта, а берёт их из **`'DIRS': [],`**  

```bash
'OPTIONS': {
    'context_processors': [
      ...
    ],
},

   ```

**`OPTIONS`** - это дополнительные настройки для шаблонизатора

**`context_processors`** - функции, которые автоматически добавляют переменные в каждый HTML‑шаблон Django

**`django.template.context_processors.request`** - Добавляет в шаблон переменную request.
Чтобы в HTML можно было использовать данные запроса

request.user — текущий пользователь

request.path — текущий URL

request.GET — параметры в URL


**`django.contrib.auth.context_processors.auth`** - Добавляет в шаблон переменные

user — текущий пользователь

perms — его права

Чтобы в HTML можно было проверять авторизацию

**`django.contrib.messages.context_processors.messages`** - Добавляет в шаблон переменную messages.
Чтобы выводить системные сообщения

INSTALLED_APPS → TEMPLATES → context_processors → HTML - запуск админки.
Вот такая крутая связь у этого чуда

```bash
WSGI_APPLICATION = 'dcrm.wsgi.application'
   ```

Это строка, которая говорит django что при запуске нужно юзать этот объект как точку входа в приложение

WSGI = Web Server Gateway Interface  
Это стандарт, который позволяет Python‑приложению общаться с веб‑сервером.

Django использует WSGI чтобы:

принимать HTTP‑запросы

передавать их в Django

возвращать HTTP‑ответы

AUTH_PASSWORD_VALIDATORS = [

Этот блок определяет правила проверки паролей при создании пользователей

в админке

```bash
LANGUAGE_CODE = 'en-us'
   ```

Язык по умолчанию

```bash
TIME_ZONE = 'UTC'
   ```
Это часовой пояс, который Django использует

для сохранения дат в базе, для отображения дат в шаблонах, для логов

```bash
USE_I18N = True
   ```

Это включает

перевод интерфейса, перевод сообщений, локализацию дат, локализацию чисел

Если поставить False то Django перестанет переводить текст

```bash
USE_TZ = True
   ```

Включение поддержки часовых поясов

Это значит

Django хранит время в базе в UTC но отображает его в локальном часовом поясе

```bash
STATIC_URL = 'static/'
   ```

задаёт URL‑префикс, по которому Django будет отдавать статические файлы (CSS, JS, изображения)
Когда в шаблонах используется {% static '...' %}, Django автоматически подставляет этот префикс
Без этой настройки админка и страницы не смогут загрузить стили и скрипты потому что Django не будет знать где искать статику

```bash
DEFAULT_AUTO_FIELD = 'django.db.models.BigAutoField'
   ```

Эта настройка говорит Django какой тип поля использовать для id во всех моделях по умолчанию
Когда создается модель и в ней не указывается поле id вручную Django всё равно создаёт его автоматически. 
Это первичный ключ, уникальный номер каждой записи в таблице

# Баги: уведомления (PR #86)

Найдено при ручном тестировании после мержа PR #86 (`django/test` → `develop`).

---


## BUG-02 — Payload в админке отображается в unicode-escape

В карточке `Notification object` поле **Payload** выглядит так (кириллица показывается в unicode-escape):

```
{
    "note": "ввввввввввв",
    "request_label": "REQ-2026-0054 — 11111111111111111111111"
}
```

Вместо читаемого: `"note": "ввввввввввв"`, `"request_label": "REQ-2026-0054 — 111..."`

---

## BUG-03 — Некрасивые названия объектов и нет отображения самого сообщения

Названия объектов в админке выглядят как `Notification object (1)` и `EmailNotification object (16)` вместо чего-то понятного (например, "Review request → ivan1 · 23 maja 2026").
Notification object показывает только метаданные (recipient, actor, kind, template_name, payload).
Само отрендеренное сообщение (то что получил пользователь) нигде не видно.

---

## BUG-04 — Уведомление не помечается как прочитанное

После того как пользователь зашёл и посмотрел уведомление:
- Бейдж на аватаре не обновляется, остаётся красным
- Нет кнопки "отметить как прочитанное"
- Поле `is_read` в модели есть, но нигде не меняется на `True`

---

## BUG-05 — Действия Send mail и Request review не отображаются в истории заявки

После отправки письма клиенту или запроса ревью через блок Actions:
- В карточке `RequestMain` нет записи об этом событии
- История заявки отслеживает только смены статуса, но не действия из Actions
- Непонятно кто и когда отправлял письма / запрашивал ревью

---

## BUG-06 — Раздел Clients недоступен ни одной роли

Сайдбар показывает раздел Clients только пользователям с правом `view_clients`.
Это право не объявлено ни в одной роли по умолчанию (нет в `crm/users/signals.py`).
Результат: ни один пользователь кроме суперюзера не видит и не может открыть раздел Clients.


## BUG-07 — Activity Log: поле "Zmień wiadomość" отображается как сырой JSON

Поле с описанием изменений показывается в виде `[{"changed": {"fields": ["Status"]}}]` вместо читаемого текста.
Хотелось бы видеть что-то вроде: "Изменено поле: Статус".

---

## BUG-08 — В разделе Clients нет кнопки "+ Add client"

Кнопка добавления клиента отсутствует даже у суперюзера.
Причина: `ClientAdmin` использует стандартный `admin.ModelAdmin` вместо Unfold-овского — Unfold не рендерит кнопку добавления для таких классов.

---

## BUG-09 — Автозаполнение телефона клиента обрезает код страны

При выборе клиента из выпадающего списка в заявке телефон вставляется без кода страны.
Пример: `+380730095835` → вставляется `0730095835`.



Причина: в `crm/clients/views.py` используется `phone.as_national` вместо `phone.as_e164` или `phone.as_international`.

---

## BUG-10 — Публичную форму заявки можно заспамить

Страница `/zetom/email/` не имеет никакой защиты от массовых отправок.
Можно отправить сотни заявок подряд — все создадутся в базе.
Нет rate limiting, капчи или любого другого ограничения.

---

## BUG-11 — Кнопка Delete внизу заявки не спрашивает причину удаления

При удалении заявки через кнопку Delete внизу страницы форма с причиной не появляется.
Заявка удаляется сразу, в историю записывается захардкоженная фраза `"Deleted via admin"`.
При удалении через блок Status справа → причина запрашивается корректно.
Причина: `delete_model` в `crm/zetom/admin/requestmain.py` не реализует запрос причины.

---

## BUG-12 — Переключение языков не работает

В интерфейсе есть переключатель языков (ru / en / pl), но переключение ни на что не влияет.
Причина: папка `locale/` пустая — файлы переводов (`.po` / `.mo`) не созданы.
Интерфейс всегда остаётся на английском независимо от выбранного языка.

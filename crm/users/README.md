## 1. Функциональное назначение

Модуль реализует систему ролевого доступа (RBAC) для CRM. Он автоматически создаёт роли, permissions, назначает их пользователям через профиль и ограничивает доступ к административным разделам. Модуль обеспечивает единый контроль прав, автоматическую инициализацию ролей и защиту критичных данных от ручного изменения.

## 2. Алгоритм работы (Логика)

После выполнения миграций запускается сигнал post_migrate для приложения users. Сигнал проверяет наличие таблиц и создаёт кастомные permissions. Затем создаются роли: Administrator, Department Head, Specialist, Auditor и custom role (all_seeing). Каждой роли назначаются соответствующие permissions. После этого модуль проходит по всем пользователям, определяет их роль через UserProfile и назначает им Django permissions. В админке доступ к моделям контролируется через методы has_view_permission, has_add_permission, has_change_permission и has_delete_permission. Для Request-моделей используется общий класс BaseRequestAdmin. Раздел «Роли» сделан некликабельным: список отображается, но открыть запись или изменить её невозможно.

## 4. Изменения в базе данных

Модуль использует существующие таблицы users_role, users_permission и users_userprofile. Новые поля не добавлялись, но автоматически создаются записи ролей и permissions.

## 5. Информационная безопасность (ISO 27001)

Логирование: модуль выводит диагностические сообщения при запуске сигналов, что позволяет отслеживать корректность инициализации RBAC.
Целостность: роли и permissions создаются автоматически и не могут быть изменены вручную через админку. Раздел «Роли» защищён от редактирования. Все проверки прав выполняются централизованно через user_has_perm, что исключает обход системы доступа.

## 6. Матрица прав доступа

Administrator — полный доступ ко всем модулям
Department Head — полный доступ к заявкам и просмотр пользователей
Specialist — создание, редактирование и просмотр заявок
Auditor — только просмотр заявок и панели мониторинга
custom role (all_seeing) — расширенный просмотр (read-only)

## 8. Инструкция для мануального тестирования

Создать нового пользователя. Ожидаемый результат: автоматически создаётся профиль и назначается роль.

Изменить роль пользователя. Ожидаемый результат: Django permissions обновляются автоматически.

Проверить доступ к RequestNull, RequestMain и Oferta. Ожидаемый результат: доступ соответствует роли.

Открыть раздел «Роли». Ожидаемый результат: список отображается, элементы некликабельны, редактирование недоступно.

Проверить работу действий в админке. Ожидаемый результат: кнопки доступны только при наличии прав edit_requests.

Перезапустить сервер после миграций. Ожидаемый результат: выводятся строки RBAC SIGNAL RUNNING FOR USERS и RBAC DEFAULT ROLES & PERMISSIONS CREATED.

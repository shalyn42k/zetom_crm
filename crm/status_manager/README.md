# Status Manager

Модуль управления статусами заявок (`RequestMain`).

---

## Статусы заявок (`RequestStatus`)

| Статус | Значение | Кто устанавливает |
|---|---|---|
| `active` | Заявка активна, ожидает работы | Автоматически (при создании или при возврате) |
| `open` | Работа по заявке идёт | Автоматически (когда дочерний документ в процессе) |
| `closed` | Все документы выполнены | Автоматически (когда все Oferta/Zlecenie/Wniosek = done) |
| `inactive` | Заявка на паузе / не выполнена | Вручную пользователем с указанием причины |
| `cancelled` | Клиент отказался | Вручную пользователем с указанием причины |
| `deleted` | Заявка удалена | Вручную пользователем с указанием причины |

---

## Как меняется статус

### Автоматически

Статус родительской заявки обновляется автоматически при каждом изменении дочерних документов (Oferta, Zlecenie, Wniosek):

```
нет детей                        → active
есть дети, хотя бы один in_progress или waiting → open
есть дети, все done              → closed
```

При удалении дочернего документа родитель возвращается в `active`.

Автоматические переходы **не пишутся** в историю изменений.

### Вручную

Пользователь может менять статус через панель статусов на странице заявки.

**Статусы без причины** (переход моментальный):
- `active`, `open`, `closed`

**Статусы с обязательной причиной** (показывается форма ввода):
- `inactive` — заявка архивируется
- `cancelled` — заявка аннулируется
- `deleted` — заявка удаляется

## Статусы дочерних документов (`Status`)

Применяется к Oferta, Zlecenie, Wniosek.

| Статус | Описание |
|---|---|
| `new` | Документ только создан |
| `in_progress` | Документ в работе |
| `waiting` | Ожидание (клиент, данные) |
| `done` | Документ выполнен |

### Разрешённые переходы

```
new → in_progress
in_progress → waiting
waiting → done
done → waiting
done → in_progress
```

Любой другой переход запрещён и вернёт ошибку.

---

## Разделы в административной панели

### Information (основной список)
Показывает заявки со статусами: `active`, `open`, `closed`.
Заявки `inactive`, `cancelled`, `deleted` скрыты.

### Cancelled
Заявки со статусом `cancelled` (отказы клиентов).
Доступно действие: **Restore** — возвращает заявку в `active`.

### Trash
Заявки со статусом `deleted` (soft-deleted через SafeDelete).
Доступны действия:
- **Restore** — восстанавливает заявку в `active`
- **Hard delete** — удаляет заявку из базы данных навсегда

## История изменений (`StatusHistory`)

Каждое ручное изменение статуса записывается в таблицу `StatusHistory`:

| Поле | Описание |
|---|---|
| `request` | Заявка |
| `old_status` | Статус до изменения |
| `new_status` | Статус после изменения |
| `reason` | Причина (обязательна для `inactive`, `cancelled`, `deleted`) |
| `changed_by` | Пользователь который изменил |
| `changed_at` | Время изменения |

История отображается на странице каждой заявки в разделе "History".

## Известные ограничения

- Автоматические переходы (`active` → `open` → `closed`) не фиксируются в `StatusHistory`.
- Статус `inactive` пока не имеет отдельного раздела в сайдбаре — заявки с этим статусом не отображаются нигде до создания раздела Archive.

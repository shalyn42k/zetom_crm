# Как работать с создание фич и новых модулей в проекте

## По веткам

В проекте используется такая система веток(**вместе с их иерархией**):
1. **`main`** — Стабильный код. Сюда пушу только Я, когда проверю весь код и он будет всем правилам поддерживаться.
2. **`develop`** — Ветка для последней мануальной проверки всеми, сюда пушит человек который проверил код тестом.
2. **`test`** — Ветка для интеграции и прогона автоматических тестов, сюда может пушить кто угодно.
4. **`feature/название_модуля`** — Ваша рабочая ветка для конкретной задачи.

---

### Как начать работу над фичей:
1. Создайте свою ветку от актуального состояния проекта:
   ```bash
   git checkout -b feature/название_модуля
   ```
2. Чтобы перейти в вашу ветку:
   ```bash
   git checkout feature/название_ветки_которую_вы_до_этого_создали
   ```

### Правила работы с ветками

Если вы начали работать над новым модулем в проекте, вы обязаны соблюдать эти правила чтобы ничего не сломать:

1. Вы обязаны сделать два **`git pull`** находясь в ветке модуля который вы прежде создали, первый делается из ветки **`origin main`**, второй из **`origin test`**.
* Дополниельно хочу упомнять что если вы делаете пустую ветку, то вы всегда ее делаете из **`origin main`**, а в **`origin test`** вы делаете пулл если вам нужно работать с строчками кода который изменил кто-то другой и они могут влиять на то что вы делали, если нет то достаточно лишь пула из основной ветки.

В итоге в терминале вам нужно вводить:
   ```bash
   git pull origin main
   git pull origin test
   ```
2. Если у вас что-то сломалось, код не работает либо что-то еще после пункта 1.
То вы решаете это сами, если это причина чисто ваша локальная - фиксите.
Если вы нашли ошибку в коде который находится либо в ветке **`main`** либо **`test`** - сообщаете.

3. После того как вы закончите работу над модулем/фичей и **ОБЯЗАТЕЛЬНО КТО-ТО УЖЕ СДЕЛАЛ MERGE ВАШЕЙ ВЕТКИ В ДРУГУЮ И ОН ПРОШЕЛ УСПЕШНО**, вы обязаны удалить свою ветку чтобы не мусорить ветками в проекте. Команды для удаления:

* Команда для удаления локально(идет первой):
   ```bash
   git branch -d название_ветки
   ```
* Команда для удаления на гите для всех(идет второй):
   ```bash
   git push origin --delete название_ветки_которую_вы_удалили_локально
   ```

---

### Внедрение новых фич

Когда вы закончили че-то делать, то чтобы внедрить правльно и все не сломать вашу ветку нужно соблюдать такой порядок.

1. Во время того как вы пишите код модуля стоит создать файл md формата в папке **zetom_crm/DOCS/**, назваз его feature/название_модуля.
2. К ветке желательно чтобы вы прилагали:
* Логику работы модуля(в текстовом виде).
* Диаграму которую вы сохраняете так же в **`zetom_crm/DOCS/DIAGRAMS`**(если логика сложная). 
> Так же вы все это дублируите челу по тестам когда закончили в лс.
3. Как это все слить в ветку test:
   ```bash
   git push origin название_вашей_ветки
   ```
   Затем зайти на гитхаб и открыть pull request для ветки test, и запулить если нет никаких конфликтов.

### Доп команды для пользованием гитом
1. Показывает изменения которые ты делал, где, когда и для чего.
   ```bash
   git status
   ```
2. Показывает все коммиты в нынешней ветке.
   ```bash
   git log
   ```
3. Подгатавливает либо один/несколько, либо все файлы к отправке на гит.
   ```bash
   git add . [либо имя файла]
   ```
4. Сохраняет твои изменения локально, **ПОЖАЛУЙСТА ПИШИТЕ ВСЕ ЧТО ВЫ ДЕЛАЛИ В ЭТОМ КОММИТЕ В СКОБОЧКАХ ЧТОБЫ ВАМ И МНЕ БЫЛО ЯСНО**.
   ```bash
   git commit -m "ваш понятный прекрасный текст"
   ```
5. Команда для отправки всего этого чуда на гит.
   ```bash
   git push origin название_ветки
   ```
6. Синхронизирует свежие изменения с гита с вашим кодом.
   ```bash
   git pull origin название_ветки
   ```

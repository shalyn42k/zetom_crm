### Структура проекта

В `crm/` лежат три приложения:

* **zetom** — основное: заявки (`RequestNull` → `RequestMain`), оферты, zlecenia, wnioski, статусы, админка
* **users** — роли и RBAC (кто что видит и редактирует)
* **notification** — рассылка уведомлений (используется в форме `/zetom/email`)

Админка кастомизирована через [django-unfold](https://unfoldadmin.com/) — отсюда декораторы `@display`, `@action`, цветные бейджи статусов и т.п.

### Че по запуску

Чтобы запустить сайт надо:

Во первых прописать свой .env по примеру из .env.example. Дальше по шагам:

1. Поднять Postgres через docker (БД крутится на порту `5434`, см. `docker-compose.yml`):
   ```bash
   docker compose up -d
   ```

2. Поставить зависимости. Можно через pip:
   ```bash
   pip install -r requirements.txt
   ```
   Или через poetry, если предпочитаете (в проекте есть `pyproject.toml` и `poetry.lock`):
   ```bash
   poetry install
   ```

3.
   ```bash
   python manage.py migrate
   ```

4.
   ```bash
   python manage.py runserver
   ```

5.
   ```bash
   python manage.py createsuperuser
   ```

Далее если все было сделано правильно, вас должно перекинуть на основную страницу, где затем надо в строке url вписать в конце /admin и залогиниться по тому логину и паролю который вы создавали в **`5.`** пункте.

### Тесты

Тесты на `zetom` лежат в `crm/zetom/tests/`. Запуск:

```bash
python manage.py test
```

Либо точечно по приложению:

```bash
python manage.py test crm.zetom
```

### Дополнительно касательно удобства в просмотре кода, в requirements.txt предустановлен 'black', используйте эти команды перед тем как что либо пушить к себе ветку либо в другую ветку.

2.

### Перемещение сайтом

В системе существует пока что два основных url под домена, первый это `admin`, второй `zetom`.

По `zetom` под домену, вы можете заходить и тестить фичи, сейчас там есть только фича через которую отправляютя smtp запросы на почту.
> дабы перейти на нее, впишите /zetom/email

Для того чтобы смотреть на имейлы у вас есть две опции:

1. Подключиться к tailscale и зайти в браузере по `mail.shalyn42k.pl`.

   > **Внимание:** на момент сейчас этот вариант **не работает у других разработчиков** — пока не разобрался как пофиксить. Будет починено, когда я полностью возьмусь за модуль `notification`. Пока что используйте вариант 2.

2. Перейти в `.env` и поставить `DEBUG = TRUE` — тогда сообщения будут писаться после отправки прямо в консоли.

Доп. Касательно заполнения заявки по /zetom/email, там очень строгая валидация NIP поэтому гляньте в forms.py я оставил работаюший 100% польский NIP(либо просто найдите в инете)
